# dawproject-malli

[Malli](https://github.com/metosin/malli) schemas for the
[DAWproject](https://github.com/bitwig/dawproject) 1.0 format. They cover all of
`Project.xsd` and `MetaData.xsd`, and there are helpers to read and write
`project.xml`, `metadata.xml` and `.dawproject` zip files.

## Data model

Every element has the same shape as a `clojure.data.xml` element, with plain
maps and vectors:

```clojure
{:tag     :Channel
 :attrs   {:id "ch1" :role :master :audioChannels 2 :solo false}
 :content [{:tag :Volume :attrs {:unit :linear :value 0.8}}]}
```

- Tag and attribute names are the XSD names.
- Attribute values are typed:
  - ints, booleans and doubles. Doubles include `##Inf`/`##-Inf`, which are written as `inf`/`-inf` like the reference implementation does.
  - Enums are keywords.
  - `xs:list` attributes (`contentType`, `labels`) are vectors.
- Child order and how many times each child may appear are checked as the XSD
  defines them, using Malli regex schemas. Errors still point at the exact
  child and attribute that is wrong.
- Attribute maps are closed, so unknown attributes are rejected.
- You can leave out `:attrs` and `:content` when nothing in them is required.

## Usage

```clojure
(require '[dawproject.schema :as ds]
         '[dawproject.xml :as dx])

(def p (dx/parse-project (slurp "project.xml"))) ; parse + decode to typed values
(ds/validate p)                  ; => true
(ds/humanize p)                  ; => nil, or a malli.error/humanize map
(ds/validate ds/StrictProject p) ; also checks that ids are unique and every IDREF resolves
(ds/reference-errors p)          ; => [] or [{:error :unresolved-idref ...}]

(dx/emit-str p)                  ; back to XML

(let [{:keys [project metadata entries]} (dx/read-dawproject "song.dawproject")]
  ...)
(dx/write-dawproject "out.dawproject" project metadata {"audio/a.wav" (io/file "a.wav")})
```

Schemas are registered in `ds/registry` (use with `ds/options`):

- `:dawproject/<Element>` for every global element, e.g. `:dawproject/Project`,
  `:dawproject/MetaData`, `:dawproject/Track`, `:dawproject/Clip`, `:dawproject/Points`.
- `:dawproject.type/<simpleType>` for simple types, e.g. `:dawproject.type/unit`,
  `:dawproject.type/timeUnit`, `:dawproject.type/double`.

`(ds/schema :dawproject/Note)` returns a compiled schema for one element.
`ds/xml-transformer` converts between raw XML strings and typed values with
`m/decode` and `m/encode`.

## Where this differs from the XSD

- **Double values:** several attributes are declared `xs:string` in the XSD
  but hold Java `Double`s in the reference implementation (through
  `DoubleAdapter`). Examples are `RealParameter@value`, `Note@time` and
  `RealPoint@value`. They are validated as doubles here.
- **Abstract elements:** `Timeline`, `Point` and `parameter` are listed inside
  choices in the XSD, but their types are abstract, so they can't appear in a
  document without `xsi:type`. They are left out.

## Tests

```
clojure -M:test
```

The tests validate and round-trip 20 projects generated by the Bitwig reference
implementation (`test-resources/reference`). They also use a hand-written
project that contains every element type (`test-resources/kitchen-sink.xml`),
and cover a set of invalid documents.
